## 2026-07-23 - Hardening State Deserialization against PHP Object Injection
**Vulnerability:** Untrusted PHP `unserialize()` was used on database-stored state data (`$staterec->additionaldata`) in `classes/loginflow/authcode.php` without disabling class instantiation, which could lead to arbitrary PHP Object Injection if an attacker could control or tamper with the database state records.
**Learning:** Even internal database-sourced serialized variables must be treated as untrusted boundaries if they are populated from external or dynamic sources. Under PHP's default behavior, deserialization without restricting allowed classes can trigger magic methods (`__wakeup`, `__destruct`, `__toString`) of any class available in the runtime, opening up a vector for Object Injection.
**Prevention:** Always restrict deserialization by passing `['allowed_classes' => false]` or a strict whitelist of class names to `unserialize()`. Additionally, ensure that inline security comments comply with Moodle's CI formatting guidelines (e.g., proper capitalization and sentence termination).
