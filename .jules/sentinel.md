## 2026-03-02 - PHP Object Injection in State Deserialization
**Vulnerability:** Insecure deserialization of OAuth state parameter data (`additionaldata`) via `unserialize()` without restricting instantiated classes.
**Learning:** The state parameter additional data is stored as a serialized string in the database and retrieved upon OAuth callback. If the stored data can be manipulated, or if other database columns are compromised/injectable, unserializing it could instantiate arbitrary classes and trigger magic methods (`__wakeup`, `__destruct`), potentially leading to PHP Object Injection and Remote Code Execution (RCE). Since the application only expects a simple array here, leaving `allowed_classes` unrestricted was an unnecessary security risk.
**Prevention:** Always restrict class instantiation when calling `unserialize()` by passing the options array `['allowed_classes' => false]` or `['allowed_classes' => [...]]` if specific classes are required. Better yet, prefer `json_decode()` and `json_encode()` for simple data structures whenever possible to avoid deserialization vulnerabilities entirely.
